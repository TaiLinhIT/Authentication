WAREHOUSE LICENSE STUDIO · TÀI LIỆU TÍCH HỢP

Một file office.dat.
Kiểm tra trước khi cho phép sử dụng.

Hướng dẫn cho người cấp license và lập trình viên đưa cơ chế bản quyền offline vào project WPF, WinForms hoặc ứng dụng Windows .NET 8.

Đối chiếu mã nguồn dự án ngày 24/10/2026. Tài liệu chạy offline, không tải thư viện hoặc hình ảnh từ Internet.

1. Cấp license2. Chuẩn bị client3. Luồng bảo vệ4. Giải mã5. Tích hợp C#6. Vận hành7. Xử lý lỗi8. Giới hạn
Phân biệt hai công việc: mỗi khách chỉ nhận office.dat. Public key và secret là dữ liệu lập trình viên chuẩn bị một lần khi build client. Private key dùng để ký luôn ở máy cấp license.

1. Cấp và giao license

  1. Mở LicenseGenerator.exe. Chọn Thêm sản phẩm, nhập tên và chọn thuật toán/kích thước khóa. RSA-3072 là cấu hình mặc định; ECDSA P-256 cũng được hỗ trợ.
  2. Đặt mật khẩu ký ít nhất 12 ký tự. Sao chép chính xác Product ID từ danh sách sản phẩm để dùng trong client. ID được tạo từ tên sản phẩm; không tự suy đoán lại ID khi tích hợp.
  3. Chuẩn bị client theo phần 2. Lấy định danh từ chính máy sẽ chạy phần mềm, không lấy từ máy cấp license.
  4. Chọn Cấp license: sản phẩm, khách hàng, trạm/PC, kiểu ràng buộc, định danh, loại license, ngày bắt đầu và hết hạn.
  5. Bấm Tạo license đã ký, nhập mật khẩu nếu phiên đang khóa. Sau đó bấm Lưu office.dat. Tạo thư mục riêng cho từng khách/trạm để tránh ghi đè các file cùng tên.
  6. Gửi duy nhất office.dat. Khách đặt file vào đường dẫn mà client đọc, ví dụ cạnh file .exe. Không bấm/chạy file .dat; ứng dụng tự đọc nó khi khởi động.
  7. Để xuất lại: mở danh sách License, bấm biểu tượng tải xuống của đúng bản ghi. Gia hạn: chọn Gia hạn, đặt thời gian mới, cấp và thay file cũ bằng file mới.

Chỉ chọn một kiểu cho mỗi license. Ứng dụng không yêu cầu đồng thời fingerprint và MAC. Không dùng địa chỉ IP trong ô MAC.

Ngày giờ và ngôn ngữ

Form dùng múi giờ Windows trên máy cấp, thể hiện cạnh ô ngày. Nhập yyyy-MM-dd, yyyy-MM-dd HH:mm hoặc yyyy-MM-dd HH:mm:ss. Không nhập giờ: có hiệu lực đến hết ngày địa phương. Có giờ: hết hạn tại thời điểm đó. License vẫn hợp lệ đúng tại thời điểm hết hạn, bị từ chối khi thời gian hiện tại vượt qua mốc đó.

Ví dụ UTC+7: nhập 2026-10-23 16:00:00 → ký 2026-10-23 09:00:00Z → hiển thị lại 16:00 trên máy UTC+7. License cũ đã ký nhầm UTC không tự sửa; phải cấp thay thế. Ngày bắt đầu có dung sai 5 phút trong thư viện hiện tại.

Nút ngôn ngữ chuyển Anh → Việt → Trung giản thể → Nhật → Anh, ghi nhớ lựa chọn. Các tên nút trong tài liệu này dùng tiếng Việt.

3. Luồng xác thực bắt buộc

OfficeLicenseFile.TryOpenForThisMachine chỉ giải mã. LicenseCrypto.Verify kiểm chữ ký và giải mã payload binary. LicenseRules.Evaluate kiểm sản phẩm, thiết bị, thời gian; không tự gọi ClockGuard. Client phải thực hiện đủ các bước.

4. office.dat được mã hóa và giải mã thế nào?

Máy cấp ký payload bằng private key RSA-PSS/SHA-256 hoặc ECDSA P-256/SHA-256, P-384/SHA-384. Envelope JSON chứa payload và chữ ký dạng Base64 được mã hóa bằng AES-256-GCM. Base64 chỉ là cách biểu diễn dữ liệu, không phải mã hóa bảo mật.

info = UTF8("OFFC1|" + ProductId.Trim().ToUpperInvariant()
                     + "|" + BindingValue.Trim().ToUpperInvariant())
key  = HKDF-SHA256(ikm = secret32Bytes, salt = salt16Bytes,
                  info = info, outputLength = 32)
plaintextJson = AES-256-GCM.Decrypt(key, nonce12Bytes, ciphertext, tag16Bytes)

Với MAC, BindingValue phải là 12 ký tự hex viết hoa không phân cách. Thư viện tự thử fingerprint, Device ID và các MAC hiện có. Mỗi lần xuất dùng salt và nonce mới nên hai file cùng license có thể khác byte nhưng đều hợp lệ.

Không chỉnh ngày hết hạn trong JSON đã giải mã. Sửa payload làm chữ ký không còn khớp. Muốn gia hạn phải ký license mới ở máy cấp. Không bao giờ lấy public key từ nội dung license để tự xác nhận chính license đó.

5. Tích hợp vào project C#

Mẫu hoàn chỉnh: examples/LicenseGate.cs. Copy vào client, thêm reference LicenseShared. File này được biên dịch cùng self-test để tránh tài liệu chứa mẫu không chạy được.

5.1 Đọc dữ liệu tin cậy từ assembly của client

using System.IO;
using System.Reflection;
using LicenseIntegration;

static string ReadEmbedded(string name)
{
    using var stream = Assembly.GetExecutingAssembly()
        .GetManifestResourceStream(name)
        ?? throw new InvalidOperationException("Thiếu tài nguyên: " + name);
    using var reader = new StreamReader(stream);
    return reader.ReadToEnd();
}

// Đặt hàm này trong client. Thay bằng Product ID đã sao chép từ Studio.
static LicenseShared.LicenseValidationResult CheckLicense()
{
    const string productId = "YOUR_PRODUCT_ID";
    string path = Path.Combine(AppContext.BaseDirectory, "office.dat");
    return LicenseGate.ValidateFile(path, productId,
        ReadEmbedded("Vendor.PublicKeys"),
        ReadEmbedded("Vendor.OfficeSecret"));
}

Ví dụ đặt office.dat cạnh .exe để đơn giản. Nếu app nằm trong Program Files, hãy dùng thư mục dữ liệu có quyền ghi hoặc để installer đặt file; sửa đường dẫn đọc tương ứng. Không ghi bản giải mã ra log.

5.2 WinForms: kiểm tra trước Application.Run

[STAThread]
static void Main()
{
    ApplicationConfiguration.Initialize();
    try
    {
        var result = CheckLicense();
        if (!result.IsValid)
        {
            MessageBox.Show(result.Message, "License");
            return;
        }
        Application.Run(new MainForm());
    }
    catch (Exception ex)
    {
        MessageBox.Show("Không thể khởi động: " + ex.Message, "License");
        // Không chạy MainForm khi cấu hình hoặc kiểm tra gặp lỗi.
    }
}

5.3 WPF: kiểm tra trước khi tạo MainWindow

// Bỏ StartupUri trong App.xaml để WPF không tự mở cửa sổ trước kiểm tra.
protected override void OnStartup(StartupEventArgs e)
{
    base.OnStartup(e);
    try
    {
        var result = CheckLicense();
        if (!result.IsValid)
        {
            MessageBox.Show(result.Message, "License");
            Shutdown(1);
            return;
        }
        MainWindow = new MainWindow();
        MainWindow.Show();
    }
    catch (Exception ex)
    {
        MessageBox.Show(ex.Message, "License");
        Shutdown(1);
    }
}

5.4 Kiểm tra lại khi app đang chạy

Dùng System.Windows.Forms.Timer cho WinForms hoặc DispatcherTimer cho WPF, ví dụ mỗi 30 phút. Trong callback, gọi lại CheckLicense(). Nếu không hợp lệ hoặc ném exception, khóa các thao tác được bảo vệ và yêu cầu license mới. Đừng chỉ hiện cảnh báo rồi cho chạy tiếp. Kiểm tra thêm ngay trước thao tác có giá trị như bắt đầu phép đo, xuất dữ liệu hoặc thực thi lệnh nghiệp vụ.

Với máy móc đang hoạt động, đưa hệ thống về trạng thái dừng an toàn theo thiết kế của project; không kết thúc tiến trình đột ngột giữa một thao tác phần cứng. Chu kỳ 30 phút có thể tạo khoảng trễ phát hiện hết hạn đến 30 phút; chọn chu kỳ và điểm kiểm tra phù hợp.

8. Phạm vi bảo vệ và kiểm tra trước khi phát hành

Đây là cơ chế cấp quyền offline, không phải hệ thống bảo mật toàn bộ project. Chữ ký ngăn sửa nội dung license và tự phát hành license khi không có private key. AES-GCM bảo vệ file và phát hiện sửa dữ liệu; secret nhúng trong client vẫn có thể bị trích xuất khi reverse engineering. Người biết secret vẫn không tạo được chữ ký hợp lệ nếu không có private key.

MAC có thể giả mạo/ngẫu nhiên hóa. Fingerprint cũng không phải định danh phần cứng bất biến. Người có quyền can thiệp chương trình có thể patch đoạn kiểm tra. ClockGuard có dung sai 10 phút và không chống được việc xóa/khôi phục trạng thái cục bộ. Nút thu hồi trong Studio chỉ đổi bản ghi tại máy cấp, không thông báo được cho client offline.

Nếu cần thu hồi từ xa, chống chia sẻ mạnh hơn hoặc quản lý nhiều máy tập trung, phải bổ sung xác thực server hoặc license ngắn hạn được gia hạn có kiểm soát. Không tự coi các chức năng đó là đã có trong dự án.

  • Test license đúng, sai sản phẩm, sai máy, sai secret và sai public key.
  • Test file thiếu, file bị sửa, license chưa hiệu lực, đã hết hạn và đồng hồ bị lùi.
  • Test lần xuất office.dat đầu tiên và sau khi mở lại Studio.
  • Test khởi động lại, thay license khi app đang mở và cập nhật bản client.
  • Đảm bảo không có private key/mật khẩu ký trong thư mục phát hành.
